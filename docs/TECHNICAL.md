# 技术记录

## 已通过的当前路径

主扬声器资源保留一个双声道PathMap：Pin17→DAC02；耳机Pin21→DAC03。两颗CS35L41读取同一立体声ASP的不同槽位，加载17AA38A9对应左右正常调音。高音Pin14也连接DAC02，由原音频状态事件跟随既有开关。

这不是四个独立声道。32bit ASP槽位描述总线时序，有效样本仍是24bit；当前配置固定48kHz。没有独立高低音软件分频。

## 播放时序与保护

当前CS35L41状态机将准备、PUP、DSP输出启用、PLL、双端就绪校验及最终解除静音分开。精确17AA38A9外部升压路径不再在GLOBAL_EN后立即锁回测试钥匙，而是在PUP和SPK_OUT_ENABLE完成后锁回，与Linux参考时序一致。失败、超时、取消、关闭及对端失败时都走清理。

此前本机原生Pin17路径已经出现PLAYBACK_ACTIVE但实听无声。本次调整时序并加入只读遥测后，用户明确确认低音出声；没有通过反复回退A/B证明时序是唯一原因，故不作唯一根因宣称。

不通过增加增益、绕过超时、旁路DSP或替换个人校准来解除静音。正常播放继续使用已有OEM保护和本机UID校准。

## 高音跟随

AppleALC原executeVerb完成后，仅对成功的相关状态命令合并事件。钩子内不等待、不额外执行codec命令。单个 `THREAD_CALL_OPTIONS_ONCE` 工作项串行处理，读取精确板号、codec身份、AFG/DAC/Pin17电源、双声道格式0x31、channel0、耳机状态及Pin14归属。

只有Pin14原处于D3、输出关闭、左右静音且连接DAC02时才接管。额外写白名单仅为Pin14 D0/D3、输出0/0x40、现有增益0下的静音和解除静音；不写DAC、Pin17、EAPD、codec系数或功放寄存器。代次变化阻止旧事件解除静音；停止、耳机选择或故障时恢复静音／关闭／D3，失败锁定。D0/D3通过有界延迟检查，稳定后不轮询。

## 失败路线

- 并行添加Pin14和Pin17 PathMap曾让AppleHDA输出format0x33四声道，低音驱动拒绝不兼容格式；不能把多条路径称为双声道镜像。
- 开机／唤醒追加Pin17 verbs不能阻止AppleHDA后续关闭该Pin。
- root常驻20ms镜像方案曾伴随登录卡顿，已停用；短时成功读回不能证明开机常驻稳定。
- 原生Pin17资源本身不是完整修复；必须与当前受保护功放驱动及高音跟随配对验证。

## 遥测边界

DSP控件地址由本机上传后读取的算法表和固件元数据解析，不硬套其他机器地址。扫读有起止时间、路由代次、序号及失败／超时标记；它不是同时刻的原始输入／输出波形。

参考机出现过实听出声但历史 `SPK_OUTPUT_POWER` 为0的记录，不能据此否定用户听到的声音或断言真实输出为0。Python3.9 macOS的time.monotonic起点也不能与内核mach_absolute_time直接比较。通用Runtime字段曾与功放专用故障字段不同步，排查时必须一起看，不只挑“通过”的字段。
